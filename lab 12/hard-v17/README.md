# ЛР №12, вариант 17 (повышенный уровень) — JWT с обновлением сессии

Короткий access token (JWT, 1 минута), refresh token с безопасной ротацией, выход с отзывом токенов,
роли user/admin и журнал входов для администратора.

## Запуск

Windows: дважды щёлкнуть `start.bat`. Или в терминале:

```bash
npm install            # один раз: Express и jsonwebtoken
npm start              # http://localhost:3000; access-токен 60 с, сессия 10 мин
npm run start:short    # access-токен 15 с, сессия 60 с — для демонстрации
npm test               # автотесты (8 обязательных сценариев + проверка ротации)
```

Секрет подписи JWT берётся из переменной окружения `JWT_SECRET` (не короче 32 символов).
Если её нет, сервер генерирует случайный секрет при каждом запуске. В репозитории секрета нет.

## Тестовые учётные записи

| Логин      | Имя                  | Роль  |
|------------|----------------------|-------|
| `student1` | Алексей Тестов       | user  |
| `student2` | Дана Тестова         | user  |
| `admin`    | Администратор (тест) | admin |

Пароли в репозитории не хранятся — в `data/users.json` только соль и хеш scrypt.

## Как устроено

- **Access token** — JWT (HS256), живёт 60 секунд. Клиент держит его только в памяти вкладки
  и отправляет в заголовке `Authorization: Bearer …`.
- **Refresh token** — случайная строка 32 байта в cookie `rt` (`HttpOnly; SameSite=Strict; Path=/api/auth`).
  На сервере хранится только её SHA-256-хеш.
- **Ротация**: каждый `POST /api/auth/refresh` меняет refresh-токен на новый. Если кто-то предъявит
  уже использованный токен — сервер закрывает всю цепочку (признак кражи).
- **Проверка JWT на сервере**: подпись, алгоритм (только HS256), срок `exp`, `iss`, `aud`, наличие `sub`, `jti`, `role`.
- **Выход** отзывает цепочку refresh-токенов и текущий access-токен (по `jti`).

## API

| Метод и адрес            | Доступ             | Ответы                                         |
|--------------------------|--------------------|------------------------------------------------|
| `POST /api/auth/login`   | все                | 200 токены, 400 пустые поля, 401 неверные данные |
| `POST /api/auth/refresh` | cookie `rt`        | 200 новые токены; 401 нет / истекла / повтор   |
| `POST /api/auth/logout`  | все                | 200, токены отозваны                           |
| `GET /api/profile`       | access-токен       | 200; 401                                       |
| `GET /api/users/:id`     | свой или admin     | 200; 401; 403 чужой; 404                       |
| `GET /api/admin/audit`   | роль admin         | 200 журнал; 401; 403                           |

## Структура

```
server.js            маршруты, проверка токенов и ролей, журнал событий
src/tokens.js        выдача и проверка JWT, ротация refresh-токенов
src/passwords.js     хеширование паролей
data/users.json      тестовые пользователи
public/              страница, стили, клиентская логика
test/auth.test.js    автотесты
```
